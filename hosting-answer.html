trinity-oaks.com — Complete Setup Guide

GitHub for the code, Cloudflare or Squarespace for hosting, Gmail (Google Workspace) for email. Step-by-step.

What you’ll have when you’re done:

  • A GitHub repository holding the source code (version control + backup).
  • The website live at https://trinity-oaks.com and https://www.trinity-oaks.com with automatic HTTPS.
  • Pushing a change to GitHub auto-deploys the site (if you choose Cloudflare).
  • A real Gmail inbox at info@trinity-oaks.com running on Google Workspace.
  • Proper SPF + DKIM + DMARC so outgoing mail doesn’t hit spam.

Pick your hosting path

Path A — GitHub + Cloudflare Pages recommended

Cost: $0 hosting, $0 DNS. Domain renewal stays where it is.

Best for: developer workflow, fast global CDN, free SSL, edit in code, auto-deploy on git push.

Tradeoff: the owner needs to edit HTML (or have you do it). No visual page builder.

Path B — GitHub + Squarespace

Cost: Squarespace plan (~$16+/mo).

Best for: the owner wants to edit pages visually in a browser.

Tradeoff: the HTML in this repo isn’t what gets served — the Squarespace dashboard is the source of truth. The GitHub repo becomes a design reference / backup, not the live site.

The rest of this guide walks Path A in full, then shows what changes for Path B. Email setup (Section 4) is identical for both paths.

Part 1 — Push the site to GitHub

The project at C:\Users\hgarza\Documents\project\handyman is not yet a git repository. We’ll initialize it, commit, and push to a new GitHub repo.

1.1 Install prerequisites (one-time)

  • Git for Windows — https://git-scm.com/download/win. After install, open a new PowerShell window so it picks up git on the PATH.
  • GitHub account — sign up at https://github.com/signup if you don’t have one. Pick a username you’re happy seeing in URLs.
  • GitHub CLI (optional but easier) — https://cli.github.com. Lets you create repos without clicking around the web UI.

1.2 Create a GitHub repository

Option 1 — via the web

  1. Go to https://github.com/new.
  2. Repository name: trinity-oaks (or trinity-oaks-site).
  3. Visibility: Public is fine for marketing sites. Private also works (Cloudflare Pages supports both).
  4. Do NOT check “Add a README” or “Add .gitignore” — the local folder already has files, and we want a clean push.
  5. Click “Create repository”. Leave the page open — you’ll need the git remote add command from it.

Option 2 — via the CLI (faster)

# From the project directory:
gh auth login            # one-time, follow the browser prompts
gh repo create trinity-oaks --public --source=. --remote=origin --push

If you use Option 2, you can skip steps 1.3 and 1.4 — the CLI initializes, commits, and pushes in one shot. The steps below cover Option 1.

1.3 Initialize git and commit the project

Open PowerShell at the project root:

cd C:\Users\hgarza\Documents\project\handyman

# Tell git who you are (one-time setup if you've never used git on this machine)

1.4 Connect to GitHub and push

Copy the remote URL from the GitHub “create repository” page (it looks like https://github.com/<your-user>/trinity-oaks.git), then:

git remote add origin https://github.com/<your-user>/trinity-oaks.git
git push -u origin main

GitHub will prompt you to authenticate the first time. Use a personal access token (paste it when prompted for “password”) or sign in via the browser if Git Credential Manager pops up.

From now on, any edit you make locally goes live with three commands: 
git add .
git commit -m "Describe what changed"
git push
Cloudflare Pages will detect the push and deploy in ~30 seconds.

Part 2A — Host on Cloudflare Pages (Path A, recommended)

Cloudflare Pages will build (well, just serve — there’s no build step) the site/ folder from GitHub, give it free HTTPS, and put it on a global CDN. Then we’ll point trinity-oaks.com at it.

2A.1 Create a Cloudflare account

  1. Sign up at https://dash.cloudflare.com/sign-up.
  2. Verify the email address Cloudflare sends.

2A.2 Create the Pages project

  1. In the Cloudflare dashboard, left sidebar: Workers & Pages → Create → Pages → Connect to Git.
  2. Authorize Cloudflare to read your GitHub repos. You can grant access to just the trinity-oaks repo (recommended) or all repos.
  3. Select the trinity-oaks repository → Begin setup.
  4. Configure the build:
    • Project name: trinity-oaks (this becomes trinity-oaks.pages.dev).
    • Production branch: main.
    • Framework preset: None.
    • Build command: leave blank.
    • Build output directory: site  (this is the important one)
    • Root directory: leave as /.
  5. Click Save and Deploy. First deploy finishes in ~1 minute. You’ll get a preview URL like https://trinity-oaks.pages.dev.
  6. Open it. Check the page renders, nav works, no console errors. Test at desktop and mobile widths (DevTools device toolbar).

2A.3 Point trinity-oaks.com at the Pages site

You have two sub-options here: move DNS to Cloudflare, or stay on the current DNS provider and just add a CNAME.

Option A (cleanest) — move DNS to Cloudflare

  1. Cloudflare dashboard → Add a Site → enter trinity-oaks.com → pick the Free plan.
  2. Cloudflare scans existing DNS and shows you what it found. Review carefully — make sure it sees any records you want to keep (it won’t see what doesn’t exist, so any missing ones must be added by hand later).
  3. Cloudflare gives you two nameservers, e.g. kira.ns.cloudflare.com and walt.ns.cloudflare.com.
  4. Log into the current registrar (Squarespace Domains — the domain inherited from Google Domains): Settings → Domains → trinity-oaks.com → Nameservers. Choose “Use custom nameservers” and replace the existing ns-cloud-c1…c4.googledomains.com entries with the two Cloudflare nameservers.
  5. Save. Nameserver changes typically propagate in 1–4 hours but can take up to 24.
  6. Back in Cloudflare, in the trinity-oaks.com DNS panel, you’ll add two records:
    TypeNameContentProxy
    CNAME@ (or trinity-oaks.com)trinity-oaks.pages.devProxied (orange cloud)
    CNAMEwwwtrinity-oaks.pages.devProxied (orange cloud)
    Cloudflare auto-flattens the apex CNAME so this is allowed even though plain DNS wouldn’t permit a CNAME on the root.
  7. In the Pages project: Custom domains → Set up a custom domain. Add trinity-oaks.com and then www.trinity-oaks.com. Cloudflare provisions an SSL certificate automatically (1–15 minutes).
  8. Decide which is canonical. Recommended: redirect www → apex. In Cloudflare: Rules → Redirect Rules → Create:
    • If “Hostname equals www.trinity-oaks.com”
    • Then “Static redirect” to https://trinity-oaks.com/$1 with status 301.

Option B — keep DNS at Squarespace, just add a CNAME

Simpler but you don’t get Cloudflare’s CDN/firewall on the apex (Squarespace doesn’t support CNAME flattening for the root):

  1. In Squarespace DNS settings, add: CNAME www → trinity-oaks.pages.dev.
  2. For the apex @, set A records to Cloudflare Pages’ published IPs (Cloudflare lists them when you add the custom domain — currently 172.66.0.96 and 162.159.140.98, but check the Pages docs at the time of setup, as these can change).
  3. In Pages → Custom domains, add both trinity-oaks.com and www.trinity-oaks.com. SSL provisions automatically.
Recommendation: Option A (move DNS to Cloudflare). It’s a one-time 5-minute change at the registrar, and afterwards everything — DNS, hosting, SSL, analytics, redirects — lives in one dashboard.

Part 3 — Set up Gmail at @trinity-oaks.com (Google Workspace)

This works identically whether DNS lives at Cloudflare or Squarespace. Only the panel you use to add records changes.

3.1 Sign up for Google Workspace

  1. Go to https://workspace.google.com → Get started.
  2. Enter business name (“Trinity Oaks Construction Company”), number of employees, and country (United States).
  3. When asked “Does your business have a domain?” choose Yes and enter trinity-oaks.com.
  4. Create the admin account — this becomes the first mailbox, e.g. info@trinity-oaks.com or hector@trinity-oaks.com.
  5. Pick a plan. Business Starter ($7/user/month) is enough — 30 GB storage, custom email, Meet, Drive, Calendar, Docs. Upgrade later if you need more storage or shared drives.
  6. Enter billing info. The first 14 days are free; cancel before then if you change your mind.

3.2 Verify domain ownership

Google needs to confirm you control trinity-oaks.com. It will give you a TXT record that looks like:

Type:  TXT
Name:  @  (or trinity-oaks.com)
Value: google-site-verification=AbCdEf1234567890_examplevalue

Add it:

  • If DNS is on Cloudflare: Cloudflare dashboard → trinity-oaks.com → DNS → Records → Add record. Type TXT, name @, content = the value Google gave you, TTL Auto, Proxy off (DNS-only).
  • If DNS is on Squarespace: Settings → Domains → trinity-oaks.com → DNS Settings → Add custom record. Same values.

Back in the Workspace setup wizard, click Verify. Usually instant; can take up to an hour.

3.3 Add the MX records (so mail can be received)

Modern Google Workspace uses a single MX record (introduced in 2023). If the setup wizard shows you 5 legacy records (aspmx.l.google.com etc.), use those instead — both still work.

TypeNamePriorityValueTTL
MX@1smtp.google.com3600

Legacy 5-record format (if Google asks for these instead):

PriorityValue
1aspmx.l.google.com
5alt1.aspmx.l.google.com
5alt2.aspmx.l.google.com
10alt3.aspmx.l.google.com
10alt4.aspmx.l.google.com

Before saving, delete any other MX records that exist. If two MX setups fight for the same domain, mail goes nowhere.

3.4 Add SPF (so outgoing Gmail isn’t flagged as spam)

Add one TXT record on the root:

Type:  TXT
Name:  @
Value: v=spf1 include:_spf.google.com ~all

If a TXT already exists on @ with v=spf1 in it (e.g. for Squarespace mail forwarding), merge them — never have two SPF records on the same name, that will silently break mail delivery.

3.5 Turn on DKIM (cryptographic signature on outgoing mail)

  1. Open the Workspace admin: https://admin.google.com.
  2. Menu → Apps → Google Workspace → Gmail → Authenticate email.
  3. Click Generate new record (2048-bit key, leave selector as google). Google shows you a TXT record that looks like: 
    Type:  TXT
Name:  google._domainkey
Value: v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEF... (long string)
  4. Add that TXT record at your DNS provider. Name field caveat: at Cloudflare, just enter google._domainkey; some providers want the fully-qualified google._domainkey.trinity-oaks.com — check what the panel expects.
  5. Wait ~10 minutes, then click Start authentication in the admin panel. Status should switch to “Authenticating email with DKIM”.

3.6 Add DMARC (tells receivers what to do with mail that fails SPF/DKIM)

Start in “none” mode so you can monitor for a few weeks before tightening:

Type:  TXT
Name:  _dmarc
Value: v=DMARC1; p=none; rua=mailto:info@trinity-oaks.com; pct=100; adkim=s; aspf=s

After 2–4 weeks of clean reports, change p=none to p=quarantine, then later to p=reject.

3.7 Create the mailboxes you actually want

In admin.google.com → Directory → Users → Add new user. Common setups for a small construction business:

  • info@trinity-oaks.com — public contact, what’s on the website and business cards.
  • hector@trinity-oaks.com — personal/owner.
  • estimates@trinity-oaks.com — if you want a separate stream for estimate requests.

Each user costs $7/month. If you want multiple addresses going to one inbox, use aliases instead (free): Directory → Users → (select user) → User information → Alternate emails.

3.8 Update the website + repo to use the new address

The current code uses the placeholder info@trinityoaksconstruction.com. Replace it site-wide with whatever you chose (likely info@trinity-oaks.com):

  • All 6 HTML files in site/ plus 404.html
  • site/js/nav.js (the mailto: fallback)
  • site/sitemap.xml and site/robots.txt if they reference the old domain

Then git add . && git commit -m "Update domain and email to trinity-oaks.com" && git push.

Part 5 — Reference: every DNS record you should end up with

If you took Path A (Cloudflare DNS + Cloudflare Pages + Google Workspace), the final DNS table for trinity-oaks.com looks like this:

TXTgoogle._domainkeyv=DKIM1; k=rsa; p=…—DNS onlyDKIM

Heads-up about overlapping TXT records on @: the SPF and the Google verification TXT both sit at the root name. That’s fine — you can have multiple TXT records on the same name. The rule that bites people is “don’t have two different SPF records,” not “don’t have multiple TXTs.”

Part 6 — Local dev setup: editor + AI “vibe coding”

“Vibe coding” just means letting an AI assistant write and edit the code while you describe what you want. This project is ideal for it — it’s plain HTML/CSS/JS, no build step, no framework, so the AI can read any file end to end and edit it directly.

Below: pick an editor, pick an AI assistant, then the workflow that ties it all together with the GitHub repo from Part 1.

  • Python 3 (optional but useful) — https://www.python.org/downloads/. Gives you python -m http.server 8080 for previewing the site locally. Check “Add Python to PATH” during install.
  • Git — already installed if you finished Part 1.

6.4 The actual vibe-coding workflow for this project

This loop takes ~30 seconds per edit:

  1. Open two terminals side by side (VS Code’s built-in terminal supports split panes).
  2. In terminal 1, start the local preview server — this must use HTTP, not file://, or the SVG backgrounds break: 
    cd C:\Users\hgarza\Documents\project\handyman\site
python -m http.server 8080
    Open http://localhost:8080 in a browser. Leave this terminal running.
  3. In terminal 2, start the AI assistant: 
    cd C:\Users\hgarza\Documents\project\handyman
claude        # or: codex
  4. Describe the change in plain English. The AI reads the relevant files, makes edits, and shows you a diff before saving. Always review diffs — even good AI sometimes touches files it shouldn’t.
  5. Refresh the browser. Verify visually at desktop (~1280px) and mobile (~390px) widths. Check the dev console for errors (F12).
  6. When happy, commit and push: 
    git add .
git commit -m "Short description of what changed"
git push
  7. If you set up Cloudflare Pages (Part 2A), the live site updates ~30 seconds after the push. Refresh https://trinity-oaks.com to confirm.

6.5 Tips for vibing well on this codebase

  • Lean on CLAUDE.md. The file at the repo root tells the AI the project’s rules (no frameworks, no CDN dependencies, nav changes must hit all 6 HTML files, etc.). Both Claude Code and Codex CLI read it automatically. If you find yourself correcting the AI repeatedly on the same thing, add it to CLAUDE.md — future sessions will respect it without being told.
  • Search-and-replace is your friend. The site duplicates the header and footer across all 6 HTML pages plus 404.html. When asking the AI to update a link, phone number, or email, explicitly say “across all HTML files” so it doesn’t stop after editing index.html.
  • Don’t let it add a build step. If the AI suggests installing Tailwind, React, a static-site generator, npm dependencies, or any kind of bundler — say no. CLAUDE.md explicitly forbids it, because the owner needs to be able to hand the site to another person who knows basic HTML.
  • Keep diffs small and commit often. One commit per logical change (“Update phone number,” “Replace project gallery placeholders,” “Tweak hero copy”). It’s easier to roll back a single bad change than to untangle a 20-file commit.
  • Use a branch for risky changes. git checkout -b try-new-hero, make experimental edits, push, see the Cloudflare Pages preview deployment URL (not production), share the link to get feedback, then either merge to main or delete the branch.
  • Test the mailto form after any contact-page edit. The form in js/nav.js builds a mailto: URL by hand. If the AI refactors that file, click submit on the contact page and confirm it still opens your mail client with the right address.

What to do next, in order

  1. Install VS Code + Node.js + your AI assistant of choice (Part 6.1–6.3) — ~20 minutes.
  2. Install Git, create the GitHub repo, push the code (Part 1) — ~20 minutes. The AI can help with this step.
  3. Create Cloudflare account, connect Pages to GitHub, confirm preview URL loads (Part 2A.1–2A.2) — ~15 minutes.
  4. Sign up for Google Workspace, do the TXT verification (Part 3.1–3.2) — ~15 minutes.
  5. Change nameservers at the registrar to Cloudflare (Part 2A.3 Option A) — ~5 minutes of work, then wait 1–4 hours for propagation.
  6. Once nameservers have switched: add MX, SPF, DKIM, DMARC, and the Pages custom-domain records all in Cloudflare DNS (Parts 2A.3 + 3.3–3.6) — ~30 minutes.
  7. Update placeholders in the repo to the real email + domain, push, verify (Parts 3.8 + 4) — ~15 minutes.

Total hands-on time: ~1.5 hours, plus a few hours of waiting for DNS to propagate. The hardest step is just the registrar nameserver change — everything else is web forms.
